# 남은 한계와 실험 기록

2026-11-04 기준. 앞부분은 **지금 남은 한계**, 뒷부분은 **왜 이렇게 만들었는지 보여 주는 실험 과정**이다.

- 수치 출처: [진행기록/](진행기록/) 의 당시 기록. 이 문서를 쓰면서 다시 측정한 값은 없다
- 비용: 건당 실측 단가로 계산한 값. OpenAI 청구 화면과 맞춰 보지 않았다
- 실험 스크립트: [../old/실험스크립트/](../old/실험스크립트/README.md). 임시 폴더에서 돌린 그대로라 경로와 입력 파일을 맞춰야 다시 돌아간다

## 먼저 알아둘 것

1. **정확도 수치는 사람이 검증한 값이 아니다.** 라벨은 AI 가 달았다. 발표에서 "사람 기준 정확도" 로 쓰면 안 된다
2. **실패 사례를 보고 만든 규칙을 같은 사례로 시험한 경우가 많다.** 그 시험에서 좋아지는 것은 당연하므로 새 기사에서도 같다는 근거가 아니다
3. **자동 실행은 3건 제한으로 두 차례만 돌렸다.** 긴 시간 켜 둔 적은 없다

### 정확도 측정

- **연결 정확도의 지금 기준은 정답지 100건의 Precision 90.2%, Recall 85.6%** 다 (2026-11-03, 백엔드1, `ai/eval/`). 두 LLM 심판 일치도 0.947 이고 사람 검수는 아니다 (`docs/decisions.md`)
- 예전 수치인 연결 Precision 100%, Recall 95.2%, 감성 Macro-F1 0.870, 요약 문장 근거 99.5% 는 AI 라벨 기준이다. 규칙을 만든 AI 가 답을 보며 채점했고 본문 앞 1,300자만 읽어서 후할 수 있다 (실험 19)
- 수정 프롬프트가 더 나은지 비교하지 못했다 (실험 20)
- 사람 라벨이 없어 실제 정확도는 모른다

### 종목 연결

- 틀린 연결: 255 에프앤가이드
- 빠진 연결: 188 오뚜기(LLM 이 안 뽑음), 1211 현대차(그룹명), 257 SK하이닉스(`삼전닉스`), 83 삼성증권·한국금융지주 (별칭 추가 뒤 다시 안 잼)
- `stock_group` 을 읽지 않아 `현대차그룹` 같은 그룹명은 연결 안 됨. 그룹명만 나온 기사를 연결 안 하는 것은 팀 정책 (`평가/라벨_기준.md` 7절)
- 비상장 자회사(하나은행, KB국민카드 등)를 상장 지주에 연결할지 판단 대기
- 명단 기사는 종목 수가 기준 아래면 안 걸림 (435·436 저PBR, 9개). 기준을 낮추면 단일 회사 기사까지 막힘
- 말머리 차단이 맞는 기사도 막을 수 있음 (118)
- 부분 문자열 비교라 `이닉스` 가 SK하이닉스에도 걸림. 명단 판단에만 쓰므로 그대로 둠

### 요약·감성

- 같은 기사도 실행마다 감성과 회사 수가 달라질 수 있음 (실험 9·11)
- 중립이어야 할 기사를 호재로 본 경우가 있음 (100·98·90·161·205)
- 이유 40자 제한을 절반 이상 넘김 (최근 260건 279/448). 프롬프트로 안 고쳐짐
- 정부·공공기관·사람이 회사 목록에 남음. 사전에 없어 연결은 안 되므로 화면 영향은 없음
- 숫자 검사는 "원문에 그 숫자가 있는지" 만 본다. 숫자가 다른 대상에 붙은 경우는 못 잡음

### 종목별 하루 요약

- 합치면서 뜻이 바뀐 사례: 원문 "두 종목을 26조6000억원 순매도" 가 삼성전자만의 일처럼 읽힘
- 조연 기사 1건뿐이면 주어 없는 문장이 됨 (063080 컴투스홀딩스)
- 기사가 많이 쌓인 날로 시험 못 함. 합치기 실제 실행은 영광·LG에너지솔루션 등 소수뿐
- 공시는 안 넣음 (팀 확인 전)
- 숫자 검사는 표현만 바꿔도 거부함 (`1.2조` → `1조2000억`). 그러면 새 기사가 올 때까지 그 종목 요약이 안 바뀜

## 3. 실험 과정

### 수집

**실험 1. 제목 유사도만으로 중복 판단**
- 왜: 같은 사건 기사가 언론사마다 나와서 비용과 화면 줄을 줄이고 싶었다
- 방법: RSS 446건의 모든 쌍(약 10만)을 글자 2개 조각 Jaccard 로 비교
- 결과: `FBI 탈취` 0.91(같은 사건)도 있지만 `시세표-3`/`-2` 0.85(다른 기사), `HLB`/`HLB제약` 0.75(다른 회사)가 있고, 같은 사건 `예탁원 뉴욕사무소` 는 0.41
- 결정: 기준을 낮추면 다른 회사 기사를 잃는다. 버리지 않고, 종목을 안 뒤에 묶기로 함 (사용자 결정)

**실험 2. 범용 본문 추출기**
- 방법: `trafilatura` 2.3.1 로 언론사별 1건 시험
- 결과: 파이낸셜만 깨끗. 한경은 "AI 추천 뉴스", 연합은 사진 설명·공유 버튼이 섞임
- 결정: 언론사가 적으니 본문 칸을 직접 지정. 뒤에 7곳까지 그대로 확장

**실험 3. 언론사 후보**
- 방법: RSS 직접 요청, robots.txt 전문 확인, 언론사당 15건 본문 추출
- 결과: 전자신문·연합인포맥스·비즈워치 15/15 성공. 구글 뉴스는 robots 금지이고 원문 주소를 못 받음. 조선비즈는 robots 가 AI 목적 보관 사본 금지
- 결정: 3곳 추가, 나머지 제외. 건수는 평일 오후 측정을 하루로 환산한 최대치 추정

### 요약 프롬프트

**실험 4. 프롬프트 1~3차 수정**
- 1차(무작위 3건): 공공기관·행사장이 회사로 나옴 → "영리 기업만", 키워드 "1~3단어 명사", 이유 50자
- 2차(샘플 40건으로 확대, 언론사별 무작위): `체결했다다` 3건, 원문 "올해 4·4분기" 를 "2024년 4분기" 로 쓴 사실 오류, 호재 쏠림 27/44
- 3차: 완전한 문장, 연도 변환 금지, 홍보성은 NEUTRAL, 기사에 없는 연도는 코드로 거부
- 결과: 문장 끝 오류 3→0, 그날 호재 비중 61%→38%, 418 사실 오류 해결
- 남음: 이유 40자 초과 48/69, 키워드 숫자 86/192 → **프롬프트로 안 고쳐지는 것을 확인**
- 한계: 의심 건만 원문 대조, 40건 전체 대조 아님

**실험 9. 기존 프롬프트 평가**
- 방법: 문제·정상 기사 10건을 3회씩(30회), DB 저장 없음. 기대값은 AI 가 정함
- 결과: 주인공 정답 24/27, 회사별 3회 일치 16·불일치 23, 363 홍보 기사 3회 모두 POSITIVE, 키워드 숫자 72/146
