# 수집 장애 대응 절차서 (2026-11-10)

수집이 막히거나 언론사가 AI 이용을 거부했을 때 **시스템이 스스로 하는 일**과 **사람이 할 일**.
틀은 NIST SP 800-34 Rev.1 비상 계획 7단계 (정책 → 영향 분석 → 예방 → 대체 전략 → 계획 문서 → 시험 → 유지).

## 1. 원칙 (정책)

- 막히면 **우회하지 않는다.** 쉬고, 알리고, 사람이 판단한다
- 언론사의 AI 이용 거부 표시를 따른다. 자동으로는 **더 조심스러운 쪽으로만** 바꾼다 (본문 요약 → 제목만 → 제외)
- robots.txt(RFC 9309)를 지키고, 수집 봇 이름에 목적과 레포 주소를 적는다

## 2. 막히면 얼마나 잃나 (영향 분석, 2026-11-10 실측)

| 출처 | 화면 소식 중 비중 | 놓친 뒤 되찾기 | 이 시간 안에 복구하면 손실 0 |
|---|---|---|---|
| DART 공시 | 37% (가장 큼) | 날짜로 다시 조회 가능 | 제한 없음 (하루 넘으면 `backfill_disclosures`) |
| 연합뉴스 (제목만) | 17% | 안 됨 | 약 2.7시간 |
| 한국경제 | 12% | 사이트맵 채우기 가능 | 약 1.7시간 |
| 파이낸셜뉴스 | 10% | 안 됨 | 약 1.7시간 |
| 비즈워치 | 9% | 안 됨 | 7일 넘음 |
| 연합인포맥스 (제목만) | 7% | 안 됨 | **약 1.4시간 (가장 짧음)** |
| 전자신문 | 4% | 안 됨 | 약 4.8시간 |
| 서울경제 (제목만) | 2% | 안 됨 | 약 23시간 |

- "이 시간 안에" = RSS 가 최근 기사 N개만 담아서, 바쁜 시간대에 N개가 채워지는 가장 짧은 시간
- 그래서 자동으로 쉬는 시간은 **최대 60분**: 그 안에 다시 시도해야 놓치는 기사가 없음
- 비중은 같은 소식 묶음 기준 상한 (묶기가 보수적이라 실제 손실은 이보다 작음)

## 3. 시스템이 스스로 하는 일 (예방·대체 전략)

| 상황 | 자동 대응 | 코드 | 근거 |
|---|---|---|---|
| 잠깐 실패 (끊김·시간 초과·5xx) | 무작위로 잠깐 쉬고 최대 3번 다시 | `core/util.py` `retry` | AWS "Exponential Backoff And Jitter"(2015), Google SRE 22장 |
| 서버가 "N초 뒤에 와" (Retry-After) | 그만큼 기다림. 30초보다 길면 그 사이트를 쉬게 함 | `retry`, `core/resilience.py` | RFC 6585 §4, RFC 9110 §10.2.3 |
| 같은 사이트가 연속 3번 실패, 또는 429·503 | **그 사이트만 쉼** 10분 → 20분 → 최대 60분. 지나면 1번 시험, 되면 다시 수집 | `core/resilience.py` (차단기) | Fowler "CircuitBreaker"(2014), Microsoft Azure "Circuit Breaker pattern" |
| robots.txt 가 429·5xx | 그 사이트 수집 안 함 (허용으로 보지 않음) | `steps/robots.py` | RFC 9309 §2.3.1.4, Google robots.txt 문서 |
| DART 020 (하루 한도 초과) | 다음 날 0시까지 DART 안 부름 | `steps/dart.py` | opendart 개발가이드 메시지 설명 |
| DART 010·011·012·901 (키·IP 문제) | 6시간 쉬고 "사람이 확인 필요" 알림 | `steps/dart.py` | 같음 |
| DART 800·900 (점검·알 수 없는 오류) | 바로 쉼 (10분부터) | `steps/dart.py` | 같음 |
| 언론사가 AI 이용 거부 표시를 새로 붙임 | 그 언론사를 **제목만**으로 (본문·LLM 안 씀, 예전 AI 결과는 다음 실행에서 지움) | `steps/rights.py`, `core/press_policy.py` | W3C TDMRep(2024), Cloudflare Content Signals(2025), EU 2019/790 4조 3항 |
| 위 상황 모두 | Slack 수집 점검 알림 (새로 생기면 1번, 계속되면 12시간마다, 풀리면 1번) | `run.py`, `core/notify.py` | NIST §3.2 (알림·대응) |

AI 이용 거부 표시를 찾는 곳:
- 기사 끝 저작권 고지의 "AI 학습·활용 금지" → 서로 다른 기사 **2건**에서 보이면 언론사 전체를 바꿈 (그 기사는 바로 본문 안 씀)
- HTML `<meta name="tdm-reservation" content="1">`, HTTP 헤더 `tdm-reservation: 1`
- 사이트 `/.well-known/tdmrep.json`, robots.txt `Content-Signal: ai-input=no` → 1번에 바꿈 (사이트가 직접 밝힌 것)
- `ai-train=no`(학습만 거부)는 요약을 막지 않음 → 그대로 (비즈워치)

## 4. 알림이 오면 (사람이 할 일)

명령은 `ai` 폴더에서. **Docker 로 수집기를 돌리면 앞에 `docker compose exec ai` 를 붙임** (상태 파일이 컨테이너 볼륨에 있음)

| Slack 알림 | 뜻 | 할 일 | 되돌리기 |
|---|---|---|---|
| `수집 쉬는 중 www.○○.com (HTTP 403, … 이후 다시 시험)` | 그 사이트가 거부·구조 변경으로 계속 실패 | 브라우저로 기사 하나 열어 보기. 구조가 바뀌었으면 `step4_body.py` `BODY_XPATH` 고침. 차단이면 우회하지 말고 6절 차선책 | 고치면 자동으로 풀림 (다음 시험이 성공). 바로 풀려면 `python -m hk_llm.core.resilience close www.○○.com` |
| `수집 쉬는 중 www.○○.com (HTTP 429 …)` | 요청이 많다고 거부 | 대개 기다리면 풀림. 계속되면 `.env` 요청 간격·`MAX_DELAY` 검토 | 자동 |
| `수집 쉬는 중 DART (하루 요청 한도 초과(020) …)` | 개인 키 하루 20,000건 넘음 | 같은 키를 다른 PC·스크립트가 같이 쓰는지 확인 (키는 남과 같이 쓰면 안 됨, 약관) | 다음 날 0시 자동 |
| `수집 쉬는 중 DART (인증키·IP 문제(011) — 사람이 확인 필요 …)` | 키가 막히거나 만료 | opendart 에서 키 상태 확인, 새 키면 `.env` `DART_API_KEY` 바꾸고 수집기 다시 켬 | `python -m hk_llm.core.resilience close DART` |
| `언론사 방침 바뀜 ○○ → TITLE_ONLY (기사 끝 고지 '…')` | 언론사가 AI 이용 거부를 새로 밝힘 | 기사 페이지에서 고지 확인 → 맞으면 `core/press_policy.py` `POLICY` 에 근거 문구와 함께 반영 (PR), `docs/decisions.md` 에 기록 | 헛걸림이면 `python -m hk_llm.core.press_policy reset ○○` |
| `피드 연속 실패`·`수집량 급감`·`멈춘 기사` | 기존 수집 점검 (`steps/health.py`) | `ai/README.md` 수집 점검 참고 | 자동 |

사람이 직접 바꾸는 명령:

| 하고 싶은 것 | 명령 |
|---|---|
| 지금 쉬는 출처 보기 | `python -m hk_llm.core.resilience` |
| 한 출처를 60분 멈춤 | `python -m hk_llm.core.resilience open DART 60 점검 공지` |
| 다시 열기 | `python -m hk_llm.core.resilience close DART` |
| 언론사별 지금 방침 보기 | `python -m hk_llm.core.press_policy` |
| 언론사를 수집에서 완전히 빼기 (RSS 도 안 받음) | `python -m hk_llm.core.press_policy exclude 연합뉴스 권리자 요청` |
| 언론사를 제목만으로 | `python -m hk_llm.core.press_policy title-only ○○ 이유` |
| 자동·사람이 바꾼 것을 지우고 기본 방침으로 | `python -m hk_llm.core.press_policy reset ○○` |
| 본문 쓰는 언론사의 AI 거부 표시 지금 확인 | `python -m hk_llm.steps.rights` |

`exclude`·`title-only` 는 급할 때 바로 멈추는 용도. 오래 갈 결정이면 `POLICY` 표를 고치는 PR 로 남김 (알림이 그때까지 계속 옴)

## 5. 시험·훈련

- 자동 시험: `python -m tests` — 가짜 429·503·403·Retry-After·DART 오류 코드·AI 금지 고지를 일부러 넣어 대응을 확인 (`tests/test_resilience.py`, `tests/test_rights.py`)
- 말로 짚는 훈련 (NIST §3.5.3 tabletop): 4절 표를 보며 "이 알림이 오면 누가 무엇을" 을 팀이 한 번 말로 따라가 보기. 결과는 사후 기록으로 남김
- 시연 날 수집이 막히면: 저장된 실제 데이터(`R__ai_data.sql`)로 화면은 그대로 보임

## 6. 오래 막히면 (차선책, 2026-11-10 공식 페이지 확인)

| 차선책 | 가능 여부 |
|---|---|
| DART 비중 유지 | 무료·상업 이용 가능 공공데이터, 개인 키 하루 20,000건 (우리는 하루 약 300번) → **가장 확실** |
| 지금 RSS + 금지 언론사는 제목·링크만 | 비용 0. 연합뉴스 저작권 규약은 "사전 서면 허가 없이 비영리 정보서비스도 불가" → 팀 판단 필요 (필요하면 `exclude`) |
| 한국언론진흥재단 뉴스토어 "인공지능용 뉴스데이터" | 정식 계약 경로. 견적 2~3영업일, 가격 비공개. 한경·파이낸셜·전자신문·비즈워치 |
| 뉴스토어 "분석용 뉴스데이터" | 가격 공개지만 **AI 활용 금지** → LLM 요약 불가 |
| 빅카인즈 Open API | 기관 협약 방식 → 2주 안 어려움 |
| 네이버 검색 API | 약관(2026-10-07)이 AI 입력·저장·가공 금지 → LLM 차선책 불가 |
| 연합 계열 정식 계약 | 계약사도 AI 서비스 사용 불가 |

## 7. 유지

- 언론사를 새로 넣을 때: `python -m hk_llm.steps.rights` 로 표시 확인 + 기사 끝 고지를 직접 보고 `POLICY` 에 근거 문구와 함께 (모르는 언론사는 기본이 제목만)
- 쉬는 시간·횟수(`FAIL_THRESHOLD`, `BASE_OPEN`, `MAX_OPEN`)는 `collect_run` 기록과 알림을 보며 조정. RSS 가 담는 시간이 줄면 `MAX_OPEN` 도 줄임
