# 결정사항 (현재 기준)

**지금 유효한 결정만** 적는다. 바뀌면 이 문서를 고치고, 바뀐 과정은 [진행기록/](진행기록/) 에 남긴다.
표시: ✅ 확정 · 🧪 팀 합의 전 테스트 가정 · ⏸ 보류

**제외** ✅
- 머니투데이: robots.txt 가 본문 수집 금지 → 본문 없음
- 이데일리: 기사 페이지가 우리 봇에게 404 → 본문 없음 (브라우저인 척 우회하지 않음)
- 매일경제: RSS 403 차단
- 네이버 뉴스(n.news.naver.com)·네이버 금융: robots.txt 전체 금지
- 구글 뉴스 RSS: robots.txt `/rss` 미허용 → 팀 판단 대기

## 2. 종목 범위 ✅

- **코스피200** (`hk_llm/data/stocks.csv` 의 `코스피200 = Y`, 현재 201개)
- 종목코드는 **문자열** (`'005930'`, `'0126Z0'` 처럼 영문 섞인 코드 있음)
- 종목 DB 테이블은 안 만듦: 종목 담당 팀원이 작업 중 → 내 파이프라인이 돌면 그때 맞춤

## 3. 처리 흐름 (RSS 실시간) ✅

```
RSS 목록 → 중복 제거 → 본문 수집 → LLM 요약 → 요약에서 종목 매칭 → 완료
              │            └ 실패 시 3번 재시도 후 버림
              └ robots 금지 기사는 처음부터 제외
요약 후 연결된 코스피200 종목이 없으면 버림 (⏸ 시장 브리핑 등에서 활용은 나중에)
```

- 버린 기사도 DB 에 **줄은 남기고 상태만 표시** → 같은 기사를 다시 받아 다시 요약하는 낭비 방지
- 네이버 API 쪽(⏸)은 반대로 매칭 → 요약 (검색어가 종목명이라 이미 매칭된 상태)

## 4. 기사 데이터 규칙 ✅

| 항목 | 규칙 |
|---|---|
| 중복 판단 | 주소에서 **추적용 꼬리만 떼고** 비교 (`utm_*`, `ref`, `input` 등). 기사 번호 꼬리(`newsId`, `idxno`)는 유지 |
| 비슷한 기사 | 다른 언론사의 같은 내용 기사는 **제목 유사도**로 묶음 (17번) |
| 언론사 이름 | 주요 언론사만 도메인→이름 표, 없으면 도메인 그대로 |
| 제목 | RSS → 원문 페이지 → 네이버 API(태그 제거) 순서로 사용 |
| 기자명 | 저장 (썸네일·카테고리는 안 함) |
| RSS 짧은 요약문 | 저장 |
| 본문 | 정제해서 저장, **7일 후 삭제** |
| LLM 요약 | **계속 보관** |
| 시간 | 전부 **KST**. 발행 시각 없으면 수집 시각으로 채움 |

## 5. DB

- ⏸ **DB 실행 방식 보류**: 처음엔 로컬 MySQL + root 로 정했으나, 팀 레포 규칙은 Docker MariaDB 11.8.9 (`stocknews`, 포트 3308, 앱 전용 계정, root 금지). 맞출지 보류
- ✅ **테이블은 백엔드가 Flyway 로 생성** (팀 규칙) → AI 는 컬럼 제안서만: [AI테이블_제안.md](AI테이블_제안.md)

| 테이블 (제안) | 내용 |
|---|---|
| `article` | 기사 1건 = 1줄. 주소·언론사·제목·기자·요약문·본문·시각·상태·LLM 요약 |
| `article_stock` | 기사 1건 : 종목 N개. 종목코드·대표 종목 여부·감성·이유 |
| `collect_run` | 실행 1번 = 1줄. 시작·끝·성공 여부·건수 → 화면의 "갱신 시각" |

- 처리 상태: `LISTED` → `FETCHED` → `SUMMARIZED` → `DONE` / 버림: `FAILED`, `SKIPPED`, `NO_STOCK`
- 종목 정보·별칭은 백엔드 테이블(`stock_info`, `stock_alias`) 을 읽음. 그 전까지는 `data/stocks.csv`

## 6. 백엔드·프론트와 주고받는 방식 🧪

화면용 데이터 예시는 [팀공유.md](팀공유.md)

| 항목 | 테스트 가정 |
|---|---|
| 전달 방식 | 공유 DB. AI 가 `article` 등에 쓰고, 백엔드는 읽기만 (팀 decisions.md 와 같은 방향) |
| 형식 | 팀 약속: API JSON 은 camelCase, 시각은 `+09:00` 포함 ISO-8601 (DB → API 변환은 백엔드) |
| 화면에 보낼 것 | 제목, 언론사, 원문 링크, 발행 시각, 기자명, 요약, 종목별 감성 + 이유 |
| 화면에 안 보낼 것 | 기사 본문 (언론사 정책: 원문 대체 금지) |
| 노출 조건 | `status = 'DONE'` 인 기사만 |
| 감성 값 | `POSITIVE` / `NEGATIVE` / `NEUTRAL` (한글 표시·색은 프론트) |
| AI 생성 표시 | 요약마다 모델명·요약 시각 저장, 문구는 프론트 |
| 갱신 주기 | 30분 |
| 묶음 요약 | 종목 + 하루 단위 (32번) |
