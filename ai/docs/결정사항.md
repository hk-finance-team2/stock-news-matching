## 3. 처리 흐름 (RSS 실시간) ✅

```
RSS 목록 → 중복 제거 → 본문 수집 → LLM 요약 → 요약에서 종목 매칭 → 완료
              │            ├ 실패 시 3번 재시도 후 버림
              │            └ 본문이 없는 기사(유료·[속보]·[표])는 재시도 없이 SKIPPED (2026-11-02)
              └ robots 금지 기사는 처음부터 제외
요약 후 연결된 종목이 없으면 버림 ✅
종목 매칭은 match_setting 점수 방식 사용 (23번에서 적용) ✅
매칭 점수: 이름이 맞으면 기본 통과(주인공 1.00, 조연 0.83), 테마가 맞으면 점수만 올림, 안 맞아도 안 깎음 🧪 (2026-11-02, 원래 공식과 달라 팀 공유 필요)
OpenAI 월 예산 50,000원 ✅
요약 모델 gpt-5.4-nano (기사 1건 약 $0.0006 실측. 하루 1,000건 월 약 $19, 최대 추정 1,600건 월 약 $30) ✅
주제 확인: 시황·전망·지표 기사와 명단 기사(본문 종목 5개 초과, 제목에 주인공이 있으면 10개 이상)는 연결 안 함, 그 밖에는 주인공·조연 모두 제목이나 본문 앞 200자에 이름이 있거나, 본문에 2번 이상 나와야 연결 🧪 (2026-11-03, 백엔드1 개선 반영)
LLM 이 뽑은 회사 목록은 article.companies 에 보관 → 매칭은 그걸로 (LLM 다시 안 부름). 백엔드 V7 ✅
종목별 하루 요약: 기사 1건은 LLM 없이, 2건 이상만 합침, 공시 제외 (32번) 🧪
자동 실행(35번): python -m hk_llm.loop. 5분마다, 하루 요약은 1시간마다. 본문·요약·공시 모두 어제 이후만, 새 기사부터. 코드 완성, 켜는 시점은 사용자 결정 ✅ (2026-11-03)
AI 서버: FastAPI 사용 (hk_llm/api.py). 수집은 서버와 별도 프로세스. 내부 토큰 필수, 같은 종목은 10분에 1번. 백엔드 POST /api/stocks/{code}/summary 가 호출 (PR #49) ✅ (2026-11-04)
역할: 뉴스 수집·종목 매칭·요약 개선과 백엔드 통합은 백엔드1, SNS 수집은 지승현 ✅ (팀 합의, docs/decisions.md 2026-11-03)
SNS 카페 글: 응답에 날짜가 없어 카페별 글 번호로 새 글 판단. 처음 보는 카페와 작은 번호는 SKIPPED. SNS summary 는 원문 미리보기라 model·summarized_at 을 비움 🧪 (2026-11-04)
간접 연결(회사 이름 없는 기사): 1차 서비스에 안 넣음. 독립 정답지 Precision 16.7% ✅ (docs/decisions.md 2026-11-04)
```

- 버린 기사도 DB 에 **줄은 남기고 상태만 표시** → 같은 기사를 다시 받아 다시 요약하는 낭비 방지
- 네이버 API 쪽(⏸)은 반대로 매칭 → 요약 (검색어가 종목명이라 이미 매칭된 상태)

## 4. 기사 데이터 규칙 ✅

| 항목 | 규칙 |
|---|---|
| 중복 판단 | 주소에서 **추적용 꼬리만 떼고** 비교 (`utm_*`, `ref`, `input` 등). 기사 번호 꼬리(`newsId`, `idxno`)는 유지 |
| 비슷한 기사 | 종목 매칭(23번) 뒤에 **같은 종목 + 제목 유사도 0.10 이상 + 24시간 이내**로 묶음 (17번, 🧪 임시값). 버리는 기사 없음. 대표 기사 ID 를 `article_stock.group_article_id` 에 저장, 칸이 생기기 전에는 건너뜀 (2026-11-03) |
| 언론사 이름 | 주요 언론사만 도메인→이름 표, 없으면 도메인 그대로 |
| 제목 | RSS → 원문 페이지 → 네이버 API(태그 제거) 순서로 사용 |
| 기자명 | 저장 (썸네일·카테고리는 안 함) |
| RSS 짧은 요약문 | 저장 |
| 본문 | 정제해서 저장, **7일 후 삭제** |
| LLM 요약 | **계속 보관** |
| 시간 | 전부 **KST**. 발행 시각 없으면 수집 시각으로 채움 |

## 5. DB

- ✅ **DB 실행 방식: 팀 공용 Docker MariaDB** 11.8.9 (`stocknews`, 포트 3308, 앱 전용 계정, root 금지) (2026-11-02). 팀 `docs/decisions.md` 2026-10-30 AI 테이블(V5) 항목과 같음
- ✅ **테이블은 백엔드가 Flyway 로 생성** (팀 규칙) → AI 는 컬럼 제안서만: [AI테이블_제안.md](AI테이블_제안.md)

| 테이블 | 내용 |
|---|---|
| `article` | 기사 1건 = 1줄. 주소·언론사·제목·기자·요약문·본문·시각·상태·LLM 요약·회사 목록(`companies`, V7) |
| `article_stock` | 기사 1건 : 종목 N개. 종목코드·대표 종목 여부·감성·이유 |
| `collect_run` | 실행 1번 = 1줄. 시작·끝·성공 여부·건수 → 화면의 "갱신 시각" |
| `stock_daily_summary` | 종목·날짜마다 1줄. 뉴스 종합 요약 (감성 비율 화면은 백엔드가 직접 셈) |

- 처리 상태: `LISTED` → `FETCHED` → `SUMMARIZED` → `DONE` / 버림: `FAILED`, `SKIPPED`, `NO_STOCK`
- 종목 정보·별칭·테마·점수 설정은 백엔드 테이블(`stock_info`, `stock_alias`, `stock_theme`, `match_setting`) 을 읽음

## 6. 백엔드·프론트와 주고받는 방식 🧪

화면용 데이터 예시는 [팀공유.md](팀공유.md)

| 항목 | 테스트 가정 |
|---|---|
| 전달 방식 | 공유 DB. AI 가 `article` 등에 쓰고, 백엔드는 읽기만 (팀 decisions.md 와 같은 방향) |
| 형식 | 팀 약속: API JSON 은 camelCase, 시각은 `+09:00` 포함 ISO-8601 (DB → API 변환은 백엔드) |
| 화면에 보낼 것 | 제목, 언론사, 원문 링크, 발행 시각, 기자명, 요약, 종목별 감성 + 이유 |
| 화면에 안 보낼 것 | 기사 본문 (언론사 정책: 원문 대체 금지) |
| 노출 조건 | `status = 'DONE'` 인 기사만 |
| 감성 값 | `POSITIVE` / `NEGATIVE` / `NEUTRAL` (한글 표시·색은 프론트). `sentiment` = 그날 주가 영향, 장기 영향은 `companies.long_term` 에 저장하고 이유 끝에 `(장기: 호재)` 로 표시 (2026-11-02) |
| AI 생성 표시 | 요약마다 모델명·요약 시각 저장, 문구는 프론트 |
| 갱신 주기 | 수집 5분 (자동 실행 전), 종목별 하루 요약 1시간 (백엔드 문서 기준) |
| 묶음 요약 | 종목 + 하루 단위 (32번) |

## 알려진 한계 ✅ (2026-11-03 사용자 결정: 더 고치지 않음)

전체 목록과 실험 과정은 [한계와_실험.md](한계와_실험.md)

- 수정 프롬프트의 효과는 비교 측정 안 함 (`old/eval/prompt_test.py` 시험 실패 후 다시 안 돌림)
- **연결 정확도는 정답지 100건 기준 Precision 90.2%, Recall 85.6%** (2026-11-03, `ai/eval/`, 두 LLM 심판 일치도 0.947, 사람 검수 아님. [docs/decisions.md](../../docs/decisions.md))
- 예전 수치(연결 Precision 100%, Recall 95.2%, 감성 Macro-F1 0.870)는 요약 모델 쪽 AI 라벨 기준이라 인용 금지

- 공시 요약: 표의 기간을 잘못 읽는 경우가 있음 (1642 보락 3분기를 `10/01~12/31` 로 씀, 원문 `07-01 ~ 09-30`). 평균 201자로 목표보다 긺

## 평가 지표 🧪 (2026-11-03, 사용자 확정, 라벨은 AI 검수 기준)

- 연결: Precision 우선, Recall, F1 / 감성: Macro-F1, 혼동표 / 요약: 문장 근거 비율, 핵심 사실 포함률
- 보조: 실행 일치율(Krippendorff α), 숫자 일치율, 규칙 위반 수
- 표본: 지금 프롬프트로 요약한 기사에서 `DONE` 50 + `NO_STOCK` 20. 목표값은 안 정하고 첫 측정을 기준선으로
