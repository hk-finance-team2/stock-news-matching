# 3. 2단계: 같은 기사 지우기 (`step2_dedup.py`, 개발순서 16번)

## 한 줄 요약

기사 주소에서 **비교용 주소 `url_key`** 를 만들고, 같은 `url_key` 는 첫 건만 남긴다. ~490건 → ~457건.

## 왜 필요한가

같은 기사를 두 번 요약하면 **OpenAI 비용 낭비**, 화면에 같은 기사 두 줄.

## 같은 기사인데 주소가 다른 경우

```
https://www.yna.co.kr/view/AKR123?input=1195m     ← 네이버에서 넘어온 표시
https://www.yna.co.kr/view/AKR123                  ← 원래 주소
```
`?` 뒤는 **추가 정보**. 그중 `input`, `ref`, `utm_…` 은 "어디서 클릭했나" 추적용이라 기사와 무관.

## `url_key` 만드는 규칙 (함수 `url_key`)

| 규칙 | 예 | 이유 |
|---|---|---|
| 추적용 꼬리 떼기 | `?ref=naver` 삭제 | 같은 기사 |
| 기사 번호 꼬리는 **남기기** | 이데일리 `?newsId=0511` 유지 | 떼면 다른 기사끼리 같아짐 |
| 남은 꼬리 이름순 정렬 | `?b=2&a=1` → `?a=1&b=2` | 순서만 다른 같은 주소 |
| 도메인만 소문자 | `WWW.Hankyung.com` → `www.hankyung.com` | 도메인은 대소문자 무관 (경로는 구분할 수 있어 그대로) |
| `#` 뒤, 끝 `/` 떼기 | `…/abc/#top` → `…/abc` | 같은 문서 |

## 코드 따라 읽기

```python
def dedup_by_url(articles):
    seen, out = set(), []
    for a in articles:
        key = url_key(a.url)
        if key in seen:          # 이미 본 주소면 건너뜀
            continue
        seen.add(key)
        out.append(replace(a, url_key=key))   # url_key 칸을 채운 복사본
    return out
```
- 실제 코드에는 주소가 500자를 넘으면 로그만 남기고 건너뛰는 줄도 있다 (DB 칸 `VARCHAR(500)`)
- `set` = 중복 없는 모음. "본 적 있나" 확인이 빠르다
- `replace(a, url_key=key)` = `a` 를 복사하면서 `url_key` 만 바꿈

## 제목이 비슷한 기사는? (17번이 뒤로 간 이유)

시험해 보니 제목만으로는 안 갈렸다 ([진행기록 17번](../진행기록/2_A_뉴스수집.md)):
- `HLB, 애프터마켓서 10%대 급등` vs `HLB제약, 애프터마켓서 10%대 급등` → 점수 0.75 인데 **다른 회사**
- 같은 사건인데 점수 0.41 인 경우도 있음

→ 종목을 알고 난 뒤(6단계 뒤)에 "같은 종목 + 비슷한 제목 + 가까운 시각" 으로 묶기로 함.
