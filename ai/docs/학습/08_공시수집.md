# 8. 공시 수집 (`dart.py`)

## 한 줄 요약

DART 공시 목록에서 **주가에 영향을 줄 만한 공시만** 골라, LLM 없이 바로 `DONE` 으로 저장한다. 비용 0.

## 왜 필요한가

공시는 회사가 직접 내는 공식 자료다. 기능정의서 필수 항목이고, 주가 변동 시점의 원인 후보로도 쓴다.

## 뉴스와 다른 점

| | 뉴스 | 공시 |
|---|---|---|
| 받는 곳 | RSS + 원문 페이지 | DART OpenAPI (인증키 필요) |
| 종목 연결 | LLM 이 뽑은 회사명으로 찾음 | **DART 가 종목코드를 줌** |
| 요약 | LLM | 제목을 그대로 씀 |
| 거치는 단계 | 1 → 6단계 전부 | 저장하면 바로 `DONE` |

## 들어가고 나오는 것

| | 내용 |
|---|---|
| 들어감 | DART `list.json` (어제~오늘, 코스피 `Y`·코스닥 `K`) |
| 나옴 | 새로 저장한 건수 |
| DB | `article` (`channel = 'DART'`, `status = 'DONE'`) + `article_stock` |

## 코드 따라 읽기

**① 주요 공시 고르기 (`important`)** — `TAKE` 에 걸리고 `SKIP` 에 안 걸리는 제목만
```
남김: 영업(잠정)실적, 단일판매·공급계약, 주요사항보고서, 공개매수신고서 …
뺌  : 증권발행실적보고서, 합병등종료보고서, 소유상황보고서, 투자설명서, 안내공시 …
```
2026-11-02 시험: 어제~오늘 공시 중 68건이 남음.

**② 키 지키기 (`_get_page`)** — DART 키는 요청 주소에 들어간다. 오류 메시지를 그대로 쓰면 로그에 키가 남으므로, **오류 종류만** 적고 원래 메시지를 버린다 (`from None`). 키는 `.env` 에만 있고 코드·Git 에 없다.

**③ 시각 (`published`)** — DART 는 날짜만 준다. 오늘 공시는 수집 시각, 어제 공시는 그날 00:00. 그래서 공시 시각은 수집 주기(5분)만큼 늦을 수 있다.

**④ 저장 (`collect_disclosures`)** — 이미 있는 공시(`url_key`)와 사전에 없는 종목은 건너뛰고 나머지를 한 번에 저장.

## 왜 감성이 전부 NEUTRAL 인가

`영업(잠정)실적` 이라는 제목만으로는 실적이 좋은지 나쁜지 알 수 없다. 모르는 걸 지어내지 않고 `NEUTRAL` 로 둔다. 호재·악재를 판단하려면 공시 원문을 읽어야 해서 다음 단계로 미뤘다.

## 공시가 실패하면

뉴스는 계속 돈다. `run.py` 가 오류를 잡아 `collect_run.error` 에 "공시 실패" 를 남기고 실행은 `SUCCESS` 로 끝낸다. `DART_API_KEY` 가 없는 팀원 PC 에서는 경고만 남기고 건너뛴다.

## 직접 해보기

```bash
python -m hk_llm.dart     # 필터·키 보호 시험 + 실제 수집 (DB 필요, 비용 없음) → ok
```

3. 제목이 `증권발행실적보고서` 인 공시는 왜 빠지나?
