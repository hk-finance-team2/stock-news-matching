# 12. SNS 수집과 여론 요약 (`sns.py`)

**한 줄 요약**: 뉴스가 많은 종목을 네이버 카페·블로그에서 검색해 쓸 만한 글만 남기고, 종목별로 LLM 을 1번 불러 글별 감성과 여론 요약을 만든다.

## 왜 필요한가

기능정의서가 커뮤니티 여론 수집과 요약을 요구한다. 네이버 종토방은 robots.txt 가 전체 금지라서, 정식 서비스의 공식 API 인 네이버 카페·블로그 검색을 대신 쓴다.

## 들어가고 나오는 것

| | 내용 |
|---|---|
| 들어감 | 네이버 검색 API `종목명 주가`, 최신순 20건 |
| 나옴 | `article` (`source_type = 'SNS'`), `article_stock` (감성·이유), `stock_daily_summary.sns_summary` |

## 코드 따라 읽기

**`top_stocks`**: 최근 24시간 뉴스가 많은 종목을 고른다. 2,655종목을 매시간 검색하면 호출 한도를 넘어서 최대 50개만 본다.

**`keep`**: 코드로 거른다. 제목에 종목명이 있어야 하고, 주식 단어가 있어야 하며, 광고·시황 모음이 아니어야 한다. 카페는 이름에 금융 단어가 있어야 한다. `HLB` 를 찾는데 제목이 `HLB제약` 이면 다른 종목이라 뺀다. 거른 글은 저장하지 않는다.

**`published`**: 카페는 시각을 안 주므로 수집 시각을 쓴다. 블로그는 날짜만 주며, 어제보다 오래된 글은 버린다.

**`collect`**: 글을 `FETCHED` 로 저장한다. 감성 칸은 필수라서 `NEUTRAL`, `분석 전` 을 넣지만 `DONE` 전에는 화면에 안 나간다.

**`summarize`**: 종목마다 글 최대 20건을 한 번에 보낸다. 글마다 부르는 것보다 싸다. LLM 이 빠뜨린 글은 재시도 횟수를 올리고, 3번째면 `FAILED` 가 된다.

**뉴스와 분리**: 4단계·5단계·하루 요약 조회에 `source_type = 'NEWS'` 조건이 있어 SNS 글이 안 섞인다.

## 직접 해보기

```bash
python -m tests                 # 규칙 시험 (비용 없음)
python -m hk_llm.steps.sns 3    # 종목 3개 실제 실행 (종목당 약 $0.001)
```

## 확인 질문

<details><summary>1. 왜 글마다 LLM 을 부르지 않나? ▶ 답 보기</summary>

비용 때문이다. 종목당 1번으로 묶으면 호출 수가 글 수가 아니라 종목 수에 맞춰진다.
</details>

<details><summary>2. 카페 글의 시각은 왜 정확하지 않나? ▶ 답 보기</summary>

네이버 카페 검색 응답에 작성 시각 칸이 없어서 수집한 시각을 저장하기 때문이다.
</details>
