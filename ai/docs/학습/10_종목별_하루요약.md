# 10. 종목별 하루 요약 (`step8_daily.py`, 개발순서 32번)

## 한 줄 요약

종목마다 오늘 기사를 모아 한 문단으로 만들어 `stock_daily_summary` 에 저장한다. 종목 화면의 "오늘 요약" 칸이 이걸 읽는다.

## 들어가고 나오는 것

| | 내용 |
|---|---|
| 들어감 | 오늘 발행된 `DONE` 뉴스 + 연결 종목 (공시 제외) |
| 나옴 | (저장한 종목 수, LLM 호출 수, 건너뛴 종목 수) |
| DB | `stock_daily_summary` 종목·날짜마다 한 줄, 다시 만들면 덮어씀 |

## 돈을 아끼는 규칙

| 상황 | 처리 | 비용 |
|---|---|---|
| 오늘 기사 1건 | 그 문장을 그대로 씀 | 0 |
| 오늘 기사 2건 이상 | LLM 으로 합침 (최신 10건까지) | 1번 |
| 저장된 기사 수와 같음 | 다시 안 만듦 | 0 |

마지막 규칙 덕분에 1시간마다 돌려도 새 기사가 없으면 비용이 없다.

## 코드 따라 읽기

**① 재료 고르기 (`_line`)** — 주인공 기사는 전체 요약, 조연 기사는 그 종목의 이유만 쓴다. 묶음 기사의 다른 회사 이야기가 이 종목에 붙지 않게 하려는 것이다.

**② 합치기 (`combine`)** — 재료를 `<news>` 로 감싸 LLM 에 보낸다. 기사에 없는 연도가 나오면 거부하고 다음 실행에서 다시 한다.

**③ 저장 (`summarize_day`)** — `ON DUPLICATE KEY UPDATE` 로 있으면 덮어쓴다. OpenAI 쪽 문제면 멈추고, 한 종목만 실패하면 그 종목만 건너뛴다.

## 아직 부족한 점

- 합치면서 뜻이 바뀔 수 있다: 원문 "두 종목을 26조6000억원 순매도" 가 삼성전자만의 일처럼 읽힌 사례가 있다
- 조연 기사 1건뿐이면 주어가 없는 문장이 된다 (예: "양극재 판매 회복과…")
- 자동 실행은 아직 없다 (35번)
