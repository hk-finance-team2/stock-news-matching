# 7. 6단계: 종목 매칭 (`step6_match.py`, 개발순서 23~25번)

## 한 줄 요약

5단계에서 LLM 이 뽑은 **회사 이름**(`article.companies`)을 종목 사전과 비교해 **종목코드**를 붙이고, `article_stock` 에 저장 → 연결된 종목이 있으면 `DONE`(화면에 나옴), 없으면 `NO_STOCK`.

## 왜 필요한가

화면은 "삼성전자 관련 뉴스" 처럼 **종목 단위**로 보여준다. 기사와 종목을 잇는 표가 `article_stock`.

## 들어가고 나오는 것

| | 내용 |
|---|---|
| 들어감 | `status = 'SUMMARIZED'` 기사의 `companies`(JSON), `keywords` + 종목 사전 |
| 나옴 | `DONE` 건수 |
| DB | `article_stock` 에 줄 추가 (기사 1 : 종목 N), `article.status` → `DONE` / `NO_STOCK` |

## 종목 사전 (백엔드가 채움, AI 는 읽기만)

| 테이블 | 내용 | 지금 |
|---|---|---|
| `stock_info` | 종목코드·종목명·시장 (V6, KRX KIND 출처) | 2,655개 (코스피+코스닥) |
| `stock_alias` | 별칭 (예: 삼전 → 삼성전자) | 496개 (헷갈리는 `AMBIGUOUS` 50줄은 안 씀) |
| `stock_theme` | 테마 (예: 한화에어로스페이스 → 방산) | 37개, 연결 1,114개 |
| `match_setting` | 점수 가중치 (V3, 요구사항 초기값) | 이름 0.4 · 테마 0.4 · 문맥 0.2, 최소 0.7 |

## 코드 따라 읽기

**① 이름 맞추기 (`norm`)** — `(주)`, `㈜`, `주식회사`, 공백을 빼고 영문은 대문자
```
"(주) LG 씨엔에스" → "LG씨엔에스"      "hl만도" → "HL만도"
```

**② 사전 읽기 (`load_dictionary`)** — `{비교용 이름: 종목코드}` (정식 이름 + 별칭), 테마, 설정값

**③ 점수 (`score`)** — 이름이 일치한 종목만 점수를 매긴다
```
주인공: (0.4×1 + 0.2×1)   ÷ 0.6 = 1.00
조연  : (0.4×1 + 0.2×0.5) ÷ 0.6 = 0.83
키워드에 테마가 있으면 0.4 를 더함 (최대 1.00), 없어도 안 깎음
```
왜 원래 공식(0.4 + 0.4 + 0.2)을 안 쓰나: 삼성전자의 `3분기 실적` 기사처럼 키워드가 테마와 다르면 0.6 으로 탈락하기 때문이다. 🧪 팀에 공유 중.

**별칭**: `alias_type = 'AMBIGUOUS'`(포스코, 모비스 등 다른 종목과 겹치는 이름)는 뺀다. 사전에 없는 회사 이름은 로그에 모아 별칭 후보로 쓴다.

**④ 한 기사 매칭 (`match_one`)** — 회사마다 사전에서 종목코드 찾기 → 사전에 없으면 버림 → 점수 미달이면 버림 → 같은 종목이 두 번 나오면 점수 높은 것 하나

**⑤ 저장 (`match_articles`)** — 기사마다 **한 덩어리(트랜잭션)** 로:
1. 그 기사의 기존 `article_stock` 줄 삭제
2. 새 연결 넣기 (`is_main`, `sentiment` 는 LLM 결과 그대로, `reason` 끝에 `(장기: 호재)` 를 붙임, `relevance` = 관련도, `evidence` = 근거 문장, `match_type = 'DIRECT'`)
3. 상태 `DONE` / `NO_STOCK`

"지우고 다시 넣기" 라서 **몇 번을 다시 돌려도 결과가 같다**. 규칙을 고친 뒤:
```python
match_articles(statuses=("SUMMARIZED", "DONE", "NO_STOCK"))   # 전부 다시 매칭, LLM 안 부름
```
이게 V7 `companies` 칸을 요청한 이유.

**점수와 관련도는 다르다.** 점수는 연결할지 정하고, 관련도(`relevance`)는 화면 순서에 쓴다. 관련도는 제목 0.40 또는 첫 부분 0.20 + 주인공 0.25 + 언급 횟수 최대 0.25 + 테마 0.10 이다. 근거 문장(`evidence`)은 그 종목 이름이 나온 본문 문장 중 LLM 이유와 단어가 가장 많이 겹치는 문장을 코드로 고른다. 둘 다 백엔드1이 추가했다.

회사 이름이 없는 기사를 영향받는 종목에 잇는 간접 연결은 정확도가 낮아서 (독립 정답지 Precision 16.7%) 1차 서비스에 넣지 않았다.

## 왜 기사 본문이 아니라 LLM 이 뽑은 이름으로 매칭하나

본문에서 종목명을 직접 찾으면:
- `HLB` 를 찾다가 `HLB제약` 기사에 걸림, `대상`·`영광` 같은 일반 단어 종목명이 아무 문장에나 걸림
- 증권사 이름(리포트 출처)·행사장 이름까지 걸림
LLM 이 "이 기사가 다룬 회사" 를 먼저 골라 주면 이런 오탐이 크게 준다. (예: `"HL만도 …" -삼성` 기사에서 삼성증권은 출처라 빠짐)

## 주제 확인 (`on_topic`, 2026-11-03)

이름이 사전에 있어도 기사 주제가 아니면 연결하지 않는다. 생산지표 기사에 삼성전자가 사례로 나왔다고 삼성전자 화면에 띄우면 안 되기 때문이다.

1. 제목에 `시황`, `증시 전망`, `산업생산` 같은 말이 있으면 연결 안 함 (`[특징주]` 는 예외)
2. 본문에 종목이 5개 넘게 나오고 제목에 주인공이 없으면 명단 기사로 보고 연결 안 함. 제목에 주인공이 있어도 10개 이상이면 연결 안 함
3. 나머지는 이름이 제목이나 본문 앞 200자에 있거나, 본문에 2번 이상 나와야 연결 (`MIN_MENTIONS`)

LLM 은 실행마다 답이 흔들리지만 이 규칙은 코드라 항상 같게 거른다. 대가는 기사 뒷부분에 1번만 나오는 회사를 놓치는 것이다. 2번 이상 조건은 2026-11-03 에 추가됐다.
