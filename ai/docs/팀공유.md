# 팀 공유 (AI 담당 → 백엔드·프론트·전체)

회의 때 이 문서를 보여주고 체크한다. 지금은 아래 **테스트 가정**으로 개발 중이고, 다르게 정해지면 그 부분만 고친다.

## 1. 합의할 질문

| # | 질문 | 누구와 | 테스트 가정 | 다르게 정하면 바뀌는 것 | 결과 |
|---|---|---|---|---|---|
| 1 | 데이터를 **공유 DB** 로 넘길까, AI 쪽이 **API** 를 만들까? | 백엔드 | 공유 DB (AI 가 쓰고 백엔드는 읽기만) | API 면 FastAPI 서버 작업 증가 | 레포 decisions.md 에 "백엔드는 AI 가 쓴 테이블을 주로 읽기만" → 같은 방향 |
| 2 | AI 테이블 컬럼 | 백엔드 | [AI테이블_제안.md](AI테이블_제안.md) | Flyway V 파일은 백엔드가 작성 | |
| 3 | **종목코드 형식** | 백엔드 | `CHAR(6)` 문자열 | 영문 섞인 코드(`0126Z0`)가 있으니 숫자 검사는 넣지 않기 | 레포 규칙과 같음 ✅ |
| 4 | 뉴스 목록에 필요한 필드가 아래 예시면 충분한가? | 프론트 | 예시대로 (썸네일 없음) | 필드 추가 시 수집 수정 | |
| 5 | 감성: 3가지(호재/악재/중립)면 되나, 점수도 필요한가? | 프론트 | 3가지 + 이유 | 점수면 LLM 출력 형식 수정 | |
| 6 | 요약 길이 몇 문장? | 프론트 | 기사당 2~3문장 | 프롬프트만 수정 | |
| 7 | 요약 실패한 기사는 숨길까? | 프론트 | 숨김 | 노출 조건 수정 | |
| 8 | 갱신 주기 30분 괜찮나? | 전체 | 30분 | 스케줄러 설정만 수정 | |
| 9 | '투자 유의 문구', 'AI 생성 표시' 문구는 프론트가 넣나? | 프론트 | 프론트 | - | |
| 10 | 거래 변동 시점과 뉴스 연결(시간 윈도 매칭)에 AI 가 줄 것 | 백엔드 | 기사 `published_at` + 종목 연결만 주면 백엔드가 매칭 | AI 가 변동 원인 요약까지 하면 요약 단계 추가 | |
| 11 | 매칭 점수 방식(`match_setting`: 종목명 0.4·테마 0.4·문맥 0.2, 최소 0.7) 을 AI 매칭에 쓸까? | 백엔드 | AI 쪽 보류 중 | 쓰면 `article_stock` 에 점수 컬럼 추가 | |
| 12 | 구글 뉴스 RSS 쓸까? (robots.txt 가 `/rss` 미허용) | 전체 | 안 씀 | - | |

**프론트가 받게 될 기사 1건 예시** (백엔드가 DB 를 읽어 팀 약속대로 camelCase + `+09:00` 로 내보낸 모양, 값은 가짜)

```json
{
  "articleId": 1024,
  "title": "삼성전자, 3분기 영업이익 시장 예상 상회",
  "press": "한국경제",
  "reporter": "홍길동",
  "url": "https://www.hankyung.com/article/2026103012345",
  "publishedAt": "2026-10-30T09:12:00+09:00",
  "summary": "삼성전자 3분기 영업이익이 시장 예상을 웃돌았다. 메모리 가격 상승이 주요 원인이다.",
  "model": "(사용 모델명)",
  "summarizedAt": "2026-10-30T09:40:11+09:00",
  "stocks": [
    {"stockCode": "005930", "stockName": "삼성전자", "isMain": true,  "sentiment": "POSITIVE", "reason": "실적이 예상보다 좋음"},
    {"stockCode": "000660", "stockName": "SK하이닉스", "isMain": false, "sentiment": "NEUTRAL", "reason": "업황 언급만 있음"}
  ]
}
```

- 테이블 제안: [AI테이블_제안.md](AI테이블_제안.md) (`article`, `article_stock`, `collect_run`)
- 백엔드는 `article.status = 'DONE'` 인 기사만 조회, 본문(`body`) 컬럼은 조회하지 않음
- "갱신 시각" = `collect_run` 에서 `status = 'SUCCESS'` 인 가장 최근 `finished_at`

## 2. AI 담당이 정한 것 (공유만)

| 정한 것 | 이유 |
|---|---|
| 뉴스는 **언론사 RSS 8개로 실시간** 수집 (한경·연합·서경·파이낸셜뉴스) | 네이버 API 는 날짜 지정이 안 되고 기사량이 많아 비용이 큼 → 과거 기록용으로만, 나중에 |
| 종목 범위 **코스피200** | 데모에 충분하고 비용 관리 가능 |
| **머니투데이·이데일리 제외** | 본문을 가져올 수 없음 (robots 금지 / 봇 차단) |
| 기사 본문은 **7일 후 삭제**, 요약은 계속 보관 | 언론사 AI 정책상 전문 영구 저장은 위험 |
| 종목 연결이 없는 경제 기사는 버림 | 나중에 시장 브리핑 기능 때 다시 검토 |

## 3. 다른 파트에서 발견한 것 (참고)

- '공시 수집'(필수)이 AI 개발 순서에 없음 → DART OpenAPI 로 가능 (무료 키, `.env.example` 에 `DART_API_KEY` 있음)
- '종토방 수집'(필수)인데 네이버 금융 robots.txt 가 전체 금지
