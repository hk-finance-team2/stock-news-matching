# 팀 공유 (AI 담당 → 백엔드·프론트·전체)

AI 쪽에서 정한 것과 화면용 데이터 모양. 지금은 이 기준으로 개발 중이고, 팀에서 다르게 정해지면 그 부분만 고친다.

## 1. AI 담당이 정한 것

| 정한 것 | 이유 |
|---|---|
| 뉴스는 **언론사 7곳 RSS 11개로 실시간** 수집 (한경·연합·서경·파이낸셜·전자신문·연합인포맥스·비즈워치) | 네이버 API 는 날짜 지정이 안 되고 기사량이 많아 비용이 큼 → 과거 기록용으로만, 나중에 |
| 종목 범위 **코스피+코스닥 전체** (`stock_info`) | 코스피200 만 하면 시험 기사 9건 중 2건만 나옴. 요약 비용은 같음 |
| **구글 뉴스·조선비즈 제외** | 구글: robots 금지, 원문 주소를 못 받음. 조선비즈: robots.txt 가 AI 목적 보관 사본 금지 |
| **머니투데이·이데일리 제외** | 본문을 가져올 수 없음 (robots 금지 / 봇 차단) |
| **한경 유료 기사(한경 프리미엄) 제외** | 결제 안내만 오고 본문이 없음, 우회하지 않음. 한경 기사의 약 1/3 |
| 기사 본문은 **7일 후 삭제**, 요약은 계속 보관 | 언론사 AI 정책상 전문 영구 저장은 위험 |
| SNS 는 **네이버 카페·블로그 검색 API** 만, 1시간마다 뉴스 많은 종목 대상 (공식 API 만 사용) | 네이버 종토방은 robots 금지. 카페는 작성 시각이 없어 수집 시각 저장, 블로그는 날짜만. 닉네임·본문 저장 안 함 |
| 종목 연결이 없는 경제 기사는 버림 | 나중에 시장 브리핑 기능 때 다시 검토 |
| 수집 주기 **5분** (`python -m hk_llm.loop` 을 켜 둘 때) | 주식 뉴스에 30분은 늦음. 기사 수가 같아 LLM 비용은 그대로 |
| 감성은 **그날 주가 기준**, 장기 판단은 이유 끝에 `(장기: 호재)` | `article_stock.sentiment` 는 그날 값 |

## 2. 화면용 데이터

**프론트가 받게 될 기사 1건 예시** (백엔드가 DB 를 읽어 팀 약속대로 camelCase + `+09:00` 로 내보낸 모양, 값은 가짜)

```json
{
  "articleId": 1024,
  "title": "삼성전자, 3분기 영업이익 시장 예상 상회",
  "press": "한국경제",
  "reporter": "홍길동",
  "url": "https://www.hankyung.com/article/2026103012345",
  "publishedAt": "2026-10-30T09:12:00+09:00",
  "summary": "삼성전자 3분기 영업이익이 시장 예상을 웃돌았다. 메모리 가격 상승이 주요 원인이다.",
  "model": "(사용 모델명)",
  "summarizedAt": "2026-10-30T09:40:11+09:00",
  "stocks": [
    {"stockCode": "005930", "stockName": "삼성전자", "isMain": true,  "sentiment": "POSITIVE", "reason": "실적이 예상보다 좋음"},
    {"stockCode": "000660", "stockName": "SK하이닉스", "isMain": false, "sentiment": "NEUTRAL", "reason": "업황 언급만 있음"}
  ]
}
```

- 테이블 제안: [AI테이블_제안.md](AI테이블_제안.md) (`article`, `article_stock`, `collect_run`)
- 백엔드는 `article.status = 'DONE'` 인 기사만 조회, 본문(`body`) 컬럼은 조회하지 않음
- "갱신 시각" = `collect_run` 에서 `status = 'SUCCESS'` 인 가장 최근 `finished_at`

## 4. 종목 매칭 점수 🧪 (2026-11-02, AI 쪽 결정, 백엔드에 공유)

`match_setting` 원래 공식(이름 0.4 · 테마 0.4 · 문맥 0.2, 최소 0.7)을 그대로 쓰면 키워드가 테마와 안 맞는 기사가 0.6 으로 탈락합니다 (예: 삼성전자 `3분기 실적`). 그래서 이렇게 바꿉니다.

- 이름(또는 별칭)이 맞으면 기본 통과: 주인공 1.00, 조연 0.83
- 키워드에 테마가 들어 있으면 `theme_weight` 만큼 올림 (최대 1.00), 안 맞아도 깎지 않음
- `AMBIGUOUS` 별칭은 매칭에서 뺌. 하이픈도 지우고 비교 (`에쓰-오일`)
- 주제 확인 (2026-11-03): 이름이 맞아도 시황·전망·지표 기사, 명단 기사(본문 종목 5개 초과, 제목에 주인공이 있으면 10개 이상)는 연결 안 함. 그 밖에는 제목이나 본문 앞 200자에 이름이 있거나, 본문에 2번 이상 나와야 연결 (2026-11-03 백엔드1 개선)

**별칭**: LG CNS, LIG D&A 는 main 의 `R__stock_alias.sql` 에 추가됨 (2026-11-04 확인). 요청할 것 없음

## 5. 백엔드·프론트 확인 부탁: 공시 표시 🧪 (2026-11-02)

공시를 뉴스와 같은 표에 저장합니다. 새 칸이나 Flyway 는 필요 없습니다.

| 칸 | 값 |
|---|---|
| `article.source_type` / `channel` | `NEWS` / `DART` (뉴스와 구분은 `channel`) |
| `press` | `전자공시(DART)` |
| `title` | `회사명 + 공시 제목` |
| `summary` | 공시 원문 LLM 요약 (2026-11-03). 요약 전·실패 시에는 제목과 같음 |
| `url` | DART 공시 원문 링크 |
| `model`, `summarized_at` | 요약되면 채워짐. **비어 있으면 AI 요약이 아니므로 "AI 요약" 표시를 붙이면 안 됨** |
| `reporter`, `keywords` | 비어 있음 (NULL) |
| `sentiment`, `article_stock.sentiment` | LLM 판단. 요약 전·실패 시 `NEUTRAL` |
| `published_at` | DART 는 날짜만 줘서 오늘 공시는 수집 시각 |

- 확인할 것: ① 화면에서 공시를 뉴스와 구분해 보여 줄지 (`channel` 기준) ② 감성 비율 집계에 공시의 NEUTRAL 을 넣을지 빼지

**SNS 도 같은 규칙** (2026-11-04): SNS 글의 `summary` 는 원문 미리보기이고 `model`·`summarized_at` 이 비어 있어 "AI 요약" 표시를 붙이면 안 됨. LLM 결과는 글별 감성·이유와 `snsSummary`

## 6. 백엔드 요청: 비슷한 기사 묶음 칸 🧪 (보낼 준비 됨, 2026-11-03. AI 코드는 칸이 생기면 자동으로 채움)

**보낼 메시지 (Slack)**

> 비슷한 기사 묶기(기능정의서 "중복 제거")용으로 칸 하나 부탁드립니다.
>
> **왜**: 같은 사건 기사가 언론사마다 나와서 종목 화면에 비슷한 줄이 여러 개 보입니다. 지우지 않고 묶어서 보여 주려고 합니다. 묶음은 종목마다 다를 수 있어서 `article_stock` 에 두면 좋겠습니다.
>
> ```sql
> ALTER TABLE article_stock
>     ADD COLUMN group_article_id BIGINT NULL
>         COMMENT '같은 사건 묶음의 대표 기사 ID. 묶이지 않으면 NULL';
> ```
>
> **화면 예시**: 종목 뉴스 목록에서 묶음당 대표 기사 1줄 + "비슷한 기사 N건"
>
> **확인 부탁**: ① 이 칸 이름·위치 괜찮은지 ② 화면에서 묶어 보여 줄지 (프론트) ③ 언제쯤 가능한지. AI 쪽은 칸이 생기면 채우기 시작합니다.

## 8. 백엔드용: "다시 생성" AI 서버 🧪 (2026-11-03)

백엔드 `POST /api/stocks/{code}/summary` (B-06) 가 부를 내부 API. 브라우저에서 바로 부르면 안 됨 (토큰 노출).

- 켜기: `ai` 폴더에서 `uvicorn hk_llm.api:app --port 8000`. 백엔드가 Docker 안에 있으면 `--host 0.0.0.0` 과 주소 `host.docker.internal:8000` 필요
- `POST /summaries/{stockCode}`, 헤더 `X-Internal-Token: <.env 의 AI_INTERNAL_TOKEN>`, 본문 없음
- 상태 확인: `GET /health`

```json
{"stockCode": "373220", "summaryDate": "2026-11-03", "newsSummary": "요약 문장", "generatedAt": "2026-11-03T15:00:34+09:00", "regenerated": true}
```

| 상황 | 응답 |
|---|---|
| 새로 만듦 | 200, `regenerated: true` |
| 10분 안에 또 부름 (앞 호출이 실패했어도) | 200, `regenerated: false`, 저장된 요약 그대로 (LLM 안 부름) |
| 오늘 기사 없음 | 200, `regenerated: false`, 요약이 있으면 그 값, 없으면 `newsSummary: null` |
| 토큰 틀림 | 401 |
| 종목코드 형식 틀림 | 422 |
| OpenAI 한도 초과 / 그 밖의 장애 | 429 / 503 |

**결과**: 백엔드 연결 완료 (PR #49, 2026-11-04). `.env` 의 `AI_INTERNAL_TOKEN`, 필요하면 `AI_SERVER_URL`
