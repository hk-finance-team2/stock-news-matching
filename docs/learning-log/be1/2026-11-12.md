## 배운 것

- **재시작 정책은 depends_on 을 안 지킴**: `docker compose up` 은 DB 가 healthy 일 때까지 기다리지만, Docker 가 컨테이너를 되살릴 때는 한꺼번에 띄움 → 앱이 스스로 의존 서비스를 기다려야 함
- **허용 여부는 세 겹**: robots.txt(기계 규칙) · 기사 끝 고지(AI 금지 문구) · 규약·약관(법적 조건). 앞의 둘만 보고 "허용"이라 판단한 것이 부족했음
- **엄격함에도 대가가 있다**: 규약 일반 조항까지 적용하면 핵심 기능(요약)이 사라짐. 결국 "무엇을 지키고 무엇을 감수하는지"를 근거와 함께 적는 것이 결정. 되돌릴 수 없는 삭제(지난 요약 약 3,900건: 한경 2,604·파이낸셜 546·전자신문 352·비즈워치 371)는 결정 전에 멈춰야 했음 → 수집기를 멈춰 일부는 막았지만, 엄격 결정 때 지운 것은 되살릴 수 없음
- **차단을 피해 이름을 바꾸는 것은 우회**: 같은 IP 에서 크롬은 되고 수집기만 403 → IP 가 아니라 우리 봇 이름표를 막은 것. 막힌 걸 알면서 다른 이름으로 들어가면 우회
- **LLM 판단도 같은 기준으로 맞춰야 설명이 됨**: 뉴스는 '기사 내용', 공시는 '주가 영향'이면 면접에서 답이 안 됨. 결과가 매번 같아야 하는 부분(해석이 갈리는 공시 유형)은 LLM 이 아니라 코드가 정함
- 학원 인터넷이 자주 끊김 → 시연은 개인 핫스팟
- **측정 없이 넣지 않는다**: 인덱스(이미 충분), RAG(쓸모가 화면에서 1%) 모두 재 보니 "안 넣는 것"이 답. 넣지 않은 이유를 숫자로 말할 수 있으면 그것도 결과
- **AI 로 만든 것도 설명할 수 있어야 내 것**: 기능을 늘리기보다 설명할 수 있는 크기로, 넣을 때마다 설명서 + 꼬리 질문
