## 배운 것

- **"추리" 대신 "독해"를 시키기:** LLM 에게 "누가 영향받을지 맞혀 봐"는 16.7%, "이 문장이 쓰여 있나?"는 훨씬 정확. 경로(지식)는 사람이 근거와 함께 넣음
- **동결과 시험지:** 연습 기사로 규칙을 고치다 보면 그 기사에만 맞음(기출 외우기) → 규칙을 고정(태그·지문)한 뒤 처음 보는 기사로 딱 한 번. 결과를 보고 고쳤으면 그 시험지는 연습용으로 내림
- **Wilson 구간:** 13개 중 7개 맞음 = 53.8% 지만 95% 구간은 29~77%. 적은 표본으로 "70%"를 말하려면 거의 다 맞아야 함 → 판정표를 미리 정함
- **사람 판정의 함정 (동의 편향):** 근거 없이 "맞음/아님"만 고르게 했더니 두 사람 모두 93개 중 "아님" 0개 → 좋은 방식·나쁜 방식이 다 100% 가 됨. **근거 문장을 붙이게 하고, 함정 문항을 섞어야** 판정이 의미가 있음
- **LLM 심판:** 생성 모델(OpenAI)과 다른 계열(Claude) 2명 + 근거 필수 + 함정 4개(모두 걸러냄) + 일치도 κ 0.78 + 사람이 20개 표본 확인(19/20). 사람은 "판단" 대신 "확인"을 할 때 빠르고 정확함
- **LLM 은 같은 질문에도 답이 흔들림:** 같은 기사를 다시 돌리니 연결 13개 중 1개만 같음 → 3번 물어 2번 이상 나온 것만 (self-consistency)
- **크롤링 속도는 예절이 아니라 실무 기준:** 지난 기사를 빠르게 받다가 비즈워치(403)·전자신문(404)이 약 1,700건째에 우리 봇을 막음 → 실시간 수집까지 멈춤. 막을 때 404 를 주는 곳도 있어서 상태 코드만 보면 못 잡음 → 실시간 RSS 를 1분마다 확인하는 장치
- **숨은 버그는 영향부터 잰다:** 공시 첨부 문서 버그는 지금까지 852건 중 0건 영향 → "고치되 다시 요약할 필요 없음"을 숫자로 말할 수 있음
