## 배운 것

- **REST vs 웹소켓 vs SSE:** REST는 필요할 때 전화로 묻기, 웹소켓은 KIS가 체결마다 밀어 주는 생중계(양방향), SSE는 우리 서버가 브라우저로 밀어 주는 방송(한 방향, `EventSource`가 알아서 다시 연결)
- **받기와 저장 분리(생산자-소비자):** 받자마자 DB에 쓰면 DB가 느릴 때 수신도 멈춤 → 받는 쪽은 대기열에 넣기만, 저장은 다른 스레드가 1초마다 묶어서
- **멱등 저장:** 재접속하면 같은 체결이 또 옴 → (종목, 날짜, 누적 거래량)을 유일 키로 + `INSERT IGNORE`. 늦게 온 옛 체결이 현재가를 덮지 않게 "누적 거래량이 더 클 때만" 덮어쓰기
- **외부 API 한도 다루기:** 캐시(같은 걸 또 묻지 않기), 줄 서기(간격 두고 부르기), 나눠 받기(한 번에 100·120개 → 여러 번 이어 붙이고 겹치는 건 시각을 키로 하나만)
- **봉 묶기:** 1분봉 → n분봉은 시가 = 첫 봉, 종가 = 마지막 봉, 고가·저가 = 최대·최소, 거래량 = 합. 구간은 장 시작 09:00부터
- **수정주가:** 액면분할 전 가격을 미리 보정한 값. 원주가로 등락률을 내면 분할한 날이 "−98% 폭락"으로 잡힘
- **N+1 다시:** 급등락 날짜 30개의 뉴스를 날짜마다 물으면 31번 왕복 → `IN (...)` 한 번 + Java에서 날짜별로 나누기
- **검증은 다른 길로 대조:** 5분봉을 1분봉으로 직접 묶은 값과 비교, 1분봉으로 만든 하루 봉을 KIS 일봉과 비교 (시·고·저·종 같음, 거래량은 시간외 제외라 3.4% 적음 = 거르기가 잘 된 증거)
- **정답지(평가 데이터):** 훈련용이 아니라 "고친 게 나아졌나"를 재는 자. 스스로 채점한 점수(P 100%)는 믿기 어려움 → 다른 심판이 만든 답안지로
- **Precision / Recall:** 연결한 것 중 맞은 비율 / 연결돼야 할 것 중 찾은 비율. 우리 원칙(잘못 연결 < 못 찾음)이라 Precision 을 지키며 Recall 을 올림
- **과적합 피하기:** 정답지를 보면서 규칙을 고르면 점수만 부풀음(시험 문제 미리 보기) → 규칙은 정답지 밖 기사에서 정하고 정답지로는 한 번만
- **원인을 단계별로 세기:** 파이프라인(LLM 추출 → 사전 → 점수 → 주제 확인)마다 몇 개가 새는지 세니 가장 큰 구멍(주제 확인 위치 조건 13/26)이 바로 보임
- **평가자 간 일치도:** 두 심판이 따로 채점해 얼마나 같은가로 정답지를 믿을 근거를 만듦 (0.947)
- **AUC:** 주인공·조연을 하나씩 뽑아 주인공 점수가 높을 확률. 0.5 = 동전 던지기
- **확실하지 않은 건 확인:** KIS 응답 칸 이름이 공식 예제에 없어서, 키를 출력하지 않는 작은 스크립트로 한 번 불러 확인한 뒤 코드 작성
